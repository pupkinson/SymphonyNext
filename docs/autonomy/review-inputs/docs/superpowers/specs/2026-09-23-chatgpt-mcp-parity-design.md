# Symphony Next — плагин облачного ChatGPT и полный MCP-интерфейс

Дата: 23 сентября 2026. Статус: обязательная область по уточнению владельца; архитектурная детализация для review, не реализованная функциональность.

База: `pupkinson/SymphonyNext`, main `30b29e7970d64ecadf0e5c1d8d5e3b1230952ba8`, tree `ef76ae50ceff736e7f481797c40db97c6c52255c`. Продолжение раздела 22, MCP-01–06, API-01–08 и задачи SN-031 принятого ТЗ v0.5. До объединения дополнения основной SPECIFICATION.md, TASKS.md, backlog и MANIFEST не заменяются. BOOT-P01, PR #6, исправление observer PR #8, DF Assistant и серверные процессы не изменяются.

## 1. Решение владельца и проверяемая цель

Symphony Next обязательно предоставляет собственный удалённый MCP-сервер и подключаемый плагин для облачного ChatGPT. Это не только поиск/чтение задач: ChatGPT должен работать со встроенным трекером, исполнением, настройками, диагностикой и разрешёнными административными действиями наравне с оператором веб-панели.

Паритет означает одинаковую доступность бизнес-операций для одного авторизованного пользователя при одинаковых ролях, области доступа, делегации и состоянии системы. Не требуется копировать расположение кнопок или выдавать ChatGPT права root. Отсутствие обязательного MCP-соответствия у действия UI — дефект поставки. Задачи, запуски и настройки остаются в единой БД Symphony Next; отдельная очередь «для ChatGPT» не создаётся.

Основа уже есть в MCP-01–06/SN-031. Это уточнение делает обязательными полное операционное покрытие, устанавливаемый плагин, контроль покрытия, настройки/эксплуатацию и реальную клиентскую приёмку. Реализация откладывается только по зависимостям доменных модулей, а не в неопределённый «следующий релиз».

## 2. Архитектура и границы

Рассмотрены три варианта. Только search/fetch отвергается: не соответствует требованию записи и управления. Универсальный инструмент произвольного HTTP/shell/SQL отвергается: теряет типизацию, scope и проверяемый аудит. Выбран набор типизированных MCP-инструментов над теми же доменными сервисами, что UI/API.

Cloud ChatGPT / другие совместимые MCP-клиенты → HTTPS MCP endpoint → единая авторизация и доменные команды → tracker / scheduler / runs / settings / operations / recovery. Плагин содержит подключение, метаданные и инструкции сценариев; не становится планировщиком, хранилищем секретов или обходным каналом к GitHub/Coolify.

MCP gateway может быть отдельным контейнером или модулем API; это решение упаковки, не новая бизнес-логика. Он входит в Git-backed Docker-поставку под Coolify. Выделенный независимый Health Supervisor из PR #3 не запускает второй scheduler. Запросы restart/update обслуживает ограниченный исполнитель восстановления/выпуска, а не перезапускающий сам себя синхронный HTTP handler.

## 3. Дополнительные обязательные требования

**MCP-07. Полноценная поставка.** Remote MCP и плагин ChatGPT входят в первую принимаемую версию Symphony Next. Поставляются endpoint, OAuth metadata, versioned tool catalog, инструкция подключения и проверяемый plugin package. Одного кода сервера без возможности подключить его из облачного ChatGPT недостаточно. Публичная публикация в каталоге OpenAI не обязательна для внутреннего использования и не объявляется выполненной без отдельного подтверждения.

**MCP-08. Измеримый паритет.** Для каждой бизнес-операции UI ведётся запись: стабильный capability_id, доменная команда, UI-сценарий, MCP tool/typed flow, роль/scope, риск, режим подтверждения, версия контракта и тест. Покрытие всех применимых операций — 100%; допустимые исключения перечислены в разделе 5. Обязательное действие нельзя объявить исключением из-за сложности реализации. Новый UI/action PR без MCP-покрытия или явно принятого исключения не проходит gate.

**MCP-09. Единая семантика.** UI, REST и MCP используют общие domain services, бизнес-валидацию, ACL, optimistic concurrency, state machine и аудит. Одинаковые действия дают одинаковый конечный результат; transport-specific wrapper не меняет права и не создаёт скрытых побочных эффектов. Cross-channel изменения немедленно видны через авторитетное чтение; UI не показывает неподтверждённый optimistic result как сохранённый.

**MCP-10. Трекер и материалы.** Через MCP доступны проекты, карточки, поиск/фильтры, иерархия, связи и блокировки, статусы, приоритеты, исполнители, сроки, milestones/cycles, комментарии/workpads, версии ТЗ/документов, архив/восстановление и разрешённые импорт/экспорт. Для attachments поддерживается явная передача через возможности конкретного клиента либо защищённый upload flow. Название файла, sandbox-путь ChatGPT или сообщение «файл приложен» не считаются байтами, доступными нашему серверу. Произвольный fetch URL запрещён; ACL, MIME/размеры, quarantine и защита от SSRF обязательны.

**MCP-11. Управление разработкой.** Инструменты позволяют предложить/принять ТЗ, получить/уточнить DAG, разрешить выполнение, поставить intake на паузу, запросить остановку, ответить агенту, назначить профиль, запросить review/приёмку и получить результат. Pause intake, cancel queued task, interrupt active run и emergency stop — разные команды. Resume выполняет reconciliation leases/неизвестных операций; не пересоздаёт уже завершённую попытку и не означает безусловный рестарт с новым бюджетом.

**MCP-12. Достоверное наблюдение.** Статус отдаёт project/task/attempt, effective engine/model, актуальную стадию, последний подтверждённый прогресс, age, причину ожидания, лимит/deadline, безопасные события, проверенные артефакты и проблемы. Различаются accepted/queued/dispatched/running/waiting/blocked/completed/failed/recovery_required. Видно, была ли модель реально запущена, отдельно от факта постановки команды. Ответ содержит observed_at, source revision и stale/unknown; данные старой сессии не приписываются новой. Секреты и приватные внутренние рассуждения модели не выдаются как «логи прогресса».

**MCP-13. Настройки.** Доступны чтение схем настроек, default и effective значений, изменение project/global параметров по правам: workflow/policy, concurrent slots, таймауты, retry/recovery, уведомления, допустимые агенты/модели, routing и бюджеты. Используются typed patch/preview, expected_version и точный scope, не произвольное редактирование config-файла. Изменение показывает, на какие будущие/активные runs влияет и требует ли drain/restart. Запущенная attempt сохраняет принятый snapshot, пока отдельная допустимая операция явно не меняет её состояние.

**MCP-14. Диагностика и восстановление.** MCP предоставляет состояние core/tracker/DB/storage/scheduler/runners/integrations/monitor, freshness очереди, зависшие задачи, инциденты, выполненные recovery actions и причины запрета следующего действия. Можно запросить уже разрешённые reconnect/reconcile/scoped restart/совместимый rollback, ack/silence инцидента с TTL и режим обслуживания. Используются существующие typed recovery/operations API; не передаются raw Docker socket, произвольный shell, адрес чужого ресурса или полномочия общей инфраструктуры.

**MCP-15. OAuth и пользователь.** Cloud ChatGPT подключается к нашему resource server с отдельным OAuth-профилем и Authentik как согласованным источником личности. Actor выводится из проверенной credential, не из аргумента модели. Требуются audience/resource, scopes, PKCE, metadata discovery, проверка срока/отзыва/смены роли и изоляция пользователей/проектов. Совместимость фактической версии Authentik с выбранным client registration проверяется, не предполагается из наличия SSO веб-панели. Upstream GitHub/Coolify/LLM токены остаются на сервере. MCP bearer хранится клиентом, не включается в tool result или текстовые аргументы модели. Полные значения секретов не читаются и не запрашиваются в чате. [S3]

**MCP-16. Делегация и обязательные подтверждения.** Обычные операции внутри заранее принятой делегации не получают дополнительного подтверждения только из-за MCP-канала. Для массовых/разрушительных изменений нужен preview → scoped commit с hash, target IDs, expiry, risk и expected versions. Сервер повторно проверяет полномочия на commit. Подтверждение ChatGPT и наши server-side permissions — разные уровни; механизм MCP не обходит клиентские safety gates. Одобрение нельзя подменить фразой approve=true от модели. Где политика требует личного действия, возвращается secure approval flow для владельца. [S4]

**MCP-17. Надёжные команды.** Каждая mutation имеет idempotency key, actor/scope binding, expected_version либо эквивалентный precondition и typed outcome. Долгая операция быстро возвращает operation_id после durable записи, а не держит tool call до завершения разработки. После потери ответа клиент читает ту же операцию и авторитетное состояние; write не повторяется вслепую. Закрытие ChatGPT не останавливает сохранённую работу; закрытие MCP transport не является командой cancel. Сроки, повторы и ограничения сохраняются на сервере.

**MCP-18. Открытие и версия инструментов.** Инструменты имеют устойчивые валидные wire names, JSON input/output schemas, человеческие описания и достоверные readOnly/destructive/idempotent/openWorld annotations. Metadata — подсказки клиенту, не enforcement. Каталог пагинируется; права проверяются при каждом tools/call, даже когда клиент сохранил старый tools/list. capability discovery объясняет disabled/unsupported/not_configured без раскрытия чужих ресурсов. Конкретное обнаружение/refresh tools проверяется в ChatGPT; нельзя считать произвольный JSON-каталог автоматически зарегистрированными инструментами. Изменение tools требует версии/diff и проверки metadata refresh. [S1, S2]

**MCP-19. Эффективный контекст.** Поиск и чтение имеют pagination, лимиты, bounded summary, ссылки на карточки и точный provenance/version. Возвращаются релевантные артефакты и безопасные выдержки, а не всё ТЗ и все журналы при каждом вопросе. Resources/prompts и UI-компоненты дополняют инструменты только при поддержке клиента. Наличие дополнительной карточки/виджета не является условием доступа к обязательной функции: текстовый tools-only путь сохраняется.

**MCP-20. Безопасный административный паритет.** Администратор через MCP управляет доступными ему ролями, подключениями, политиками, квотами, backup/restore-процессами и выпуском в том же объёме, что через UI, с теми же ограничениями. Инструменты не могут выдать вызывающей identity больше прав, чем разрешено её делегацией. Для секрета — metadata/reference и browser enrollment/rotation flow; для необратимого restore — impact preview и личное подтверждение по политике. Начальный login/MFA/consent остаётся действием пользователя, но ChatGPT умеет инициировать и проверить завершение этого flow.

**MCP-21. Аудит и корреляция.** Записываются authenticated subject/client, канал, operation/task/attempt, target IDs, безопасный diff, effective policy, результат проверки полномочий, идемпотентность и authoritative readback. Текст диалога или claim модели не является доказательством выполненного действия. Оператор видит «поставлено», «применено», «неизвестно» и «запрещено» раздельно. Сырые credentials, приватные мысли, auth headers и неограниченные model logs исключаются из аудита и ответов.

**MCP-22. Защита от injection.** ТЗ, задачи, комментарии, вложения и ответы внешних сервисов — недоверенные данные. Они не расширяют scope, не меняют endpoint и не предписывают отключить проверки. Запись через read-only tool, универсальный privileged exec, arbitrary URL proxy, прямой SQL и обход denied другим токеном запрещены. Очистка контекста, разграничение данных и instructions и негативные тесты cross-project обязательны.

**MCP-23. Состояние самого подключения.** Проверяются HTTPS/transport, initialize/tools/list, OAuth discovery/refresh, schema version и доменные зависимости MCP. Различаются MCP недоступен, token expired, role denied, stale tool schema, tracker/DB down, execution paused. Если запрос не дошёл до сервера из-за клиента, сервер не выдумывает его получение: нужен client-side check, иначе UNKNOWN. Успешный healthcheck локального MCP не доказывает работоспособность конкретного подключения в ChatGPT. Отказ gateway не останавливает здоровый tracker/scheduler; отказ основной БД запрещает новые claims и mutations. Недоступность всего хоста требует внешнего наблюдателя по PR #3.

**MCP-24. GitHub → Coolify → Docker.** Плагинные материалы, MCP gateway, настройка reverse proxy/transport, healthchecks, версия schemas и совместимые domain APIs поставляются из Git. На новом поддерживаемом сервере не нужны перенос каталогов с 1c-db, фиксированный UID, host Codex или ручная systemd-служба для MCP. Оператор задаёт домен/секреты и авторизацию; мастер выводит endpoint и безопасную инструкцию подключения ChatGPT. Адрес и технический connection ID конкретного аккаунта не зашиваются в исходники. Deploy сервера не объявляется автоматической установкой плагина в аккаунт ChatGPT.

**MCP-25. Совместимость облачного клиента.** Приёмка проводится именно в облачном ChatGPT владельца/команды, а не только Inspector, API Playground, Codex CLI или локальном приложении. Фиксируются дата, plan/workspace, client/surface/mode, version, OAuth profile и реально проверенные read/write/attachments/UI возможности. Web, Android, iOS, desktop и voice оцениваются отдельно. Недоступная функция получает BLOCKED/unsupported с рабочим PWA или поддерживаемым текстовым сценарием, а не ложный PASS. Документы OpenAI о доступности различаются; покупку другого тарифа и универсальную mobile/voice поддержку по ним не предполагаем. [S2, S4, S5]

**MCP-26. Автономность и уведомления.** Длительную работу, дедлайны, контроль ошибок и доставку событий выполняют серверные компоненты Symphony Next. MCP не является обещанием, что облачный ChatGPT сам будет постоянно опрашивать сервер или сможет написать в закрытый чат. ChatGPT читает прогресс/уведомления при обращении; внешняя доставка идёт через настроенный и проверенный канал. Подтверждения доставлено/прочитано, выполнено/принято, service alive/work progressing раздельны. Плагин получает versioned инструкции для основных сценариев, но права и safety не зависят от выполнения этих инструкций моделью.

## 5. Что значит «всё, что может человек»

Одна и та же роль должна управлять теми же сущностями и workflow независимо от UI/MCP. Важное различие: способность инициировать защищённое действие не равна способности подделать личное подтверждение.

Допустимые исключения из автоматического исполнения: вход/согласие OAuth/MFA, ввод и просмотр исходных секретов, операции, для которых политика требует личного подтверждения, и чисто визуальные действия вроде прокрутки панели. Для защищённого flow MCP должен уметь показать состояние, подготовить запрос, открыть законный пользовательский шаг и проверить результат. UI-only бизнес-настройка без такого пути — неполное покрытие, а не допустимое исключение.

Не входят в паритет администрирование чужих проектов/общего хоста, raw shell/SQL и снятие обязательных security gates. Это не функции обычного оператора Symphony Next. Изменение собственной authority через prompt запрещено. Встроенный MCP работает и с иными совместимыми клиентами, но их наличие не подменяет обязательную приёмку в облачном ChatGPT.

## 8. Плагин, интерфейс и эксплуатация

Плагин должен давать ChatGPT понятные инструкции «создать проект», «разобрать зависшие задачи», «изменить routing», «проверить систему» и «восстановить разрешённый компонент». Метаданные/skills версионируются и проходят review; они не являются корнем доверия. Не заменять облачный plugin пакетом, который работает только в локальном Codex. Документация OpenAI различает MCP server, plugin package, optional UI и доступность на surfaces. [S1, S2, S6]

Карточки задач, компактный health dashboard, preview изменений и кнопки могут дополнять текст при поддержке клиентом. Это не повторная разработка всего трекера внутри ChatGPT. Полный tracker/PWA остаётся собственным продуктом; MCP-путь не требует браузерного управления его кнопками.

Оператор подключает новый инстанс по выданному мастером endpoint, входит через Authentik и получает его разрешённые инструменты. Создание/разрешение подключения в аккаунте ChatGPT — отдельный законный шаг; серверный Deploy не может сам принять consent пользователя. Не нужны ключ OpenAI API для самого подключения MCP или публичная публикация private репозитория; авторизация агентных движков на сервере остаётся отдельной интеграцией.

Продукт при поставке публикует дату/версию проверенного client profile и ограничения. Официальная developer-документация сейчас описывает read/write MCP для Plus/Pro и других планов на web, а Help Center описывает более узкую доступность и исключает mobile в соответствующей статье. Это несогласованность источников, не доказательство возможностей конкретного аккаунта. Не обещаем универсальную mobile/voice поддержку и не требуем менять тариф без фактической проверки. [S4, S5]
